# PlanScope · Codex 订阅光谱

PlanScope 用固定采样方式分析 Codex 兼容中转接口的订阅等级分布。填写接口地址和 API Key、选择模型后，系统会执行 100 个逻辑样本，从响应中的 `tier` 信息识别 Pro、Plus、Team、K12 以及未来出现的任意新等级，并生成实时看板和管理历史。

> **重要说明**
>
> PlanScope 展示的是一次采样中的**路由观测分布**，不是中转池的真实账号库存，也不能证明某个终端账号的官方订阅状态。结果依赖上游是否真实返回并透传 Codex 订阅字段。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 自动读取模型 | 请求 `GET /v1/models`，优先推荐 `gpt-5.5`，其次推荐 `gpt-5.4` |
| 固定分布采样 | 首样本识别成功后采集至 100 个逻辑样本，最大并发 50，每个样本最多尝试 5 次 |
| 动态订阅分类 | 不维护 tier 白名单，任何非空新等级都会成为独立分类 |
| 实时分析看板 | 展示进度、百分比、平均响应、100 格请求光谱和逐次请求证据 |
| 管理后台 | 查看分析汇总，以及仅保留 24 小时的隐私化请求与完整上游流式明细 |
| 隐私最小化 | API Key 只用于当前上游请求，不写入历史、日志、导出文件或浏览器存储 |
| 安全请求边界 | 包含 SSRF、DNS 重绑定、重定向、跨站请求、资源上限和接口滥用防护 |

PlanScope 默认只监听本机地址，也支持在明确配置 HTTPS、可信代理和访问限制后进行受控部署。

## 快速开始

### 运行要求

- Node.js 20 或更高版本
- 无第三方运行时依赖
- 一个你有权使用的 Codex/OpenAI Responses API 兼容地址和 API Key

### 启动项目

```bash
git clone https://github.com/d100000/Codex-ana.git
cd Codex-ana
npm start
```

服务启动后：

1. 打开 <http://127.0.0.1:4317>。
2. 填写接口根地址、`/v1` 地址或完整的 `/v1/responses` 地址。
3. 填写 API Key，点击“读取模型”。
4. 选择本次分析模型，点击“开始 100 次分析”。
5. 完成滑块验证，等待实时看板完成采样。
6. 打开 <http://127.0.0.1:4317/admin> 查看历史汇总。

本机未配置管理密码时，启动终端会显示本次运行的临时管理密码。服务重启后，该临时密码会变化。

## 分析流程

一次完整分析依次执行：

1. 规范化用户输入的 API 地址，移除查询参数和片段。
2. 读取模型列表并给出推荐项。
3. 用户选择模型并完成一次性滑块验证。
4. 服务端再次读取模型列表，确认所选模型仍然可用。
5. 单独运行首个订阅字段预检样本；请求失败或未识别到订阅字段时立即停止。
6. 首个样本识别成功后，以最多 50 并发执行剩余样本。
7. 聚合所有成功、未识别和失败结果。
8. 任务结束后，将不含凭据的汇总写入管理历史。
9. 将每次上游尝试的脱敏请求摘要、完整 SSE 事件序列和结果写入 24 小时请求日志。

完成、失败或取消都会进入明确的终态：服务端主动关闭进度 SSE，浏览器停止计时与重连、解除输入锁定并清除本次任务句柄。失败前已经完成的样本仍保留在看板中，便于核查，但不会继续占用实时连接或误触发后续请求。

### 极短流式探测请求

每个样本统一向 OpenAI Responses API 的 `POST /v1/responses` 发送请求，并以 SSE 流式读取结果：

- 提示词：`Reply exactly OK.`
- 最大输出：16 tokens
- `store: false`
- `stream: true`
- 请求头 `Accept: text/event-stream`
- 支持时使用 `reasoning.effort: none`，否则使用兼容的最低开销档位

请求不加载工具，也不要求推理摘要，目的是尽快获得响应头和订阅元数据。服务端会逐块解析并按顺序保留每个 `response.*` SSE 事件，以 `response.completed` 或 `response.incomplete` 作为完整终止事件；`[DONE]` 标记也会单独记录。流式 `error`、`response.failed`、无终止事件和超限响应均不会被误计为“未识别”。对于未正确设置 SSE `Content-Type`、但仍返回标准事件流的中转站，会使用受限的兼容解析；返回普通 JSON 的兼容中转也会作为一条兼容响应记录保存。

## 订阅等级如何判定

PlanScope 按以下优先级读取订阅信息：

1. 响应头 `x-codex-plan-type`
2. 响应体 `plan_type` 或 `planType`
3. 响应体 `error.plan_type` 或 `error.planType`
4. 响应体 `rate_limits.plan_type` 或 `rateLimits.planType`

如果成功响应中没有这些字段，该样本记为“未识别”。当首个样本未识别时，
任务会返回“无法获取订阅数据”并停止剩余 99 次请求；系统不会根据模型名称、
请求价格或限额大小猜测订阅等级。

当一次完整分析没有识别到任何订阅等级、但存在成功响应时，看板会提示
“请上游开放订阅字段透传”。这表示中转接口可以正常返回 Responses 流，
但没有透传 `x-codex-plan-type`、`plan_type` 等订阅字段；需要由上游开放
这些字段后才能进行可靠识别。

| 样本状态 | 含义 |
| --- | --- |
| 已识别 | 响应中出现了可用的 tier 字段 |
| 未识别 | 请求成功，但响应没有可用的 tier 字段 |
| 失败 | 网络、超时或上游 HTTP 错误在重试后仍未成功 |

除 tier 外，当前任务页面还会显示 `x-codex-active-limit`、主/次额度窗口、Credits 状态、服务器模型和上游请求 ID，便于逐条核验。点击样本时才会按需读取该次成功响应的完整流式事件，避免 100 个样本在实时进度中反复传输大段正文；失败尝试会同时显示失败前已经收到的事件、安全请求正文、HTTP 元数据和脱敏后的上游返回报错。这些逐次证据不会进入长期管理历史，只会进入保留 24 小时的请求日志。

## 固定采样与重试

- 每次分析固定为 100 个逻辑样本。
- 最大并发为 50。
- 每个逻辑样本最多尝试 5 次，包含首次请求。
- 只重试网络错误、超时以及 HTTP `408`、`409`、`425`、`429`、`500`、`502`、`503`、`504`。
- 每次重试前随机等待 1–3 秒。
- 每个逻辑样本使用独立会话标识；同一样本的重试复用该标识。
- 百分比始终以 100 个逻辑样本为分母。

极端情况下，一次分析最多产生 500 次 Responses 请求。开始前请确认上游额度、费率限制和服务条款。

## 模型读取与选择

每次分析前都应点击“读取模型”。系统会请求当前地址的 `GET /v1/models`：

- 精确的 `gpt-5.5` 优先于其他模型。
- 没有 `gpt-5.5` 时，精确的 `gpt-5.4` 优先。
- 用户可以改选接口返回的任意模型。
- 创建任务后，服务端会再次核验模型，防止使用已下线或被替换的 ID。
- 中转站没有实现模型列表接口时，页面会明确标记“兼容候选”，不会把候选模型冒充为实测结果。

模型列表读取同样受到 IP 和设备限频：默认每 5 分钟最多 6 次。

## 管理后台

分析页右上角提供“管理后台”入口，也可以直接访问 `/admin`。

后台提供：

- 历史任务数、接口域名数、完成/失败数量和近 24 小时记录数
- 按域名或模型搜索
- 按完成、失败、取消状态筛选
- 分页加载
- 动态 tier 占比预览
- 单次任务样本、尝试、响应时间和完整占比详情
- 最近 24 小时的请求方法、路由、状态码和耗时日志
- 每次上游请求的域名、模型、样本、尝试次数、判定结果和脱敏返回内容
- 成功或失败请求的完整 SSE 事件序列，列表只返回摘要，点击后再读取明细
- 按域名、模型、路由、错误码、请求 ID、方法或响应状态筛选请求日志

### 历史记录的隐私边界

| 会保存 | 不会保存 |
| --- | --- |
| 规范化 Origin 和域名 | API Key |
| 分析时间和任务状态 | 完整接口路径和 URL 查询参数 |
| 所选模型 | 任务 ID 和匿名设备 ID |
| 完成、识别、未识别、失败数量 | 原始响应和逐次样本证据 |
| 动态 tier 名称、数量和百分比 | 错误原文和请求头 |
| 平均响应、任务耗时和累计尝试 | 用户填写的其他凭据 |

默认历史文件为 `.data/analysis-history.json`：

- `.data/` 已加入 `.gitignore`
- 文件权限为 `0600`
- 使用同目录临时文件和原子替换写入
- 默认最多保留 5,000 条记录

### 请求日志与 24 小时保留

请求审计日志独立保存在 `.data/request-log.ndjson`。普通站内请求只包含：

- 请求时间、方法和白名单路由模板
- HTTP 状态码、处理耗时和内部错误码
- 随机请求 ID
- 经过 HMAC 处理并截断的来源与设备摘要

每次 `POST /v1/responses` 尝试都会在同一文件中保存一条上游记录。成功响应记录最终采用的结果；失败后重试的每次尝试也分别留痕：

- 接口域名、模型、逻辑样本编号和尝试次数
- 固定探针的请求方法、无查询参数地址、安全请求头和字段白名单正文
- 上游 HTTP 状态、Content-Type、请求 ID、CF-Ray 与 Retry-After
- 按接收顺序保存的全部 SSE 事件、终态事件、传输类型和响应字节数
- 失败时最多 4 KB 的额外错误正文，以及是否被截断
- 判定结果、订阅等级、命中字段、本地错误代码、错误信息和耗时

所有流式事件和错误正文都会先按当前 API Key 精确脱敏，再清除 Bearer 凭据、
`sk-` 形式令牌以及常见 token、secret、password、Cookie 字段。
Authorization、Cookie、API Key、URL 查询参数、原始 IP 和原始设备 ID
不会写入日志。未知路由统一记录为 `/[unmatched]`，任务路径中的 UUID
会替换为路由模板 `:jobId`。

单次上游响应最多读取 512 KiB、最多解析 10,000 个事件；单条持久化流式
记录额外受 768 KiB 限制。请求日志同时受记录数和总文件容量限制，默认
最多 20,000 条且不超过 256 MiB。达到上限时优先移除最旧记录，避免完整
流式响应耗尽磁盘。后台列表不会直接携带事件正文，只有管理员打开明细时
才读取单条完整记录。

日志在写入和后台读取时立即排除超过 24 小时的记录，服务端还会
每 5 分钟执行一次磁盘清理。默认最多保留 20,000 条，即使 24 小时内
请求量更高也不会无限增长。

可自定义保存目录和容量：

```bash
PLANSCOPE_DATA_DIR=/var/lib/planscope \
MAX_HISTORY_RECORDS=10000 \
MAX_REQUEST_LOG_RECORDS=50000 \
MAX_REQUEST_LOG_BYTES=536870912 \
npm start
```

### 管理员认证

本机模式未配置 `ADMIN_PASSWORD` 时，每次启动会生成一个临时密码并打印到终端。建议固定配置长随机密码：

```bash
ADMIN_PASSWORD='请替换为至少16字节的长随机密码' \
ADMIN_SESSION_SECRET='请替换为至少32字节的随机值' \
npm start
```

- 管理会话有效期为 8 小时。
- 会话 Cookie 使用 `HttpOnly` 和 `SameSite=Strict`。
- 会话与当前匿名设备绑定。
- 连续 5 次登录失败后，IP 和设备都会被限制 15 分钟。
- HTTPS 公网模式会增加 `Secure` 和 `__Host-` Cookie 约束。
- 公网模式不会自动生成临时密码；未配置 `ADMIN_PASSWORD` 时，管理登录保持禁用。

生产环境应通过密钥管理服务注入管理密码和会话签名密钥，不要把它们提交到仓库。

## 安全设计

### API Key 生命周期

API Key 会从浏览器通过当前 PlanScope 服务发送到用户指定的上游，仅用于模型读取和本次分析：

- 不写入浏览器存储
- 不写入任务快照或管理历史
- 不写入 JSON/CSV 导出
- 不写入请求日志；失败日志只接收已脱敏的固定探针字段和上游错误摘录
- 上游在错误或元数据中回显 Key 时会进行精确脱敏
- 失败正文还会进行通用 Bearer、`sk-` 令牌和敏感字段二次脱敏
- 任务结束后会从任务凭据对象中清空
- URL 或模型名称中包含当前 API Key 时直接拒绝请求

公网使用时必须启用 HTTPS，否则传输链路本身无法保护用户填写的凭据。

### 上游 SSRF 防护

所有携带 API Key 的上游请求都会经过专用安全请求器：

- 默认只允许 HTTPS 和 443 端口
- 校验域名解析出的全部地址
- 拒绝回环、RFC 1918、链路本地、共享地址、组播、保留地址和云元数据网段
- 兼容 Clash 等代理的 `198.18.0.0/15` Fake-IP；只有固定 DoH
  服务二次解析为公网地址后才放行
- 校验完成后把实际连接固定到已验证 IP，降低 DNS 重绑定风险
- 不跟随上游重定向，避免 Key 被转发到其他地址
- 上游响应体最大 512 KiB
- 请求体、响应头、DNS 解析和请求时长均有独立限制
- 支持精确的上游域名和端口允许列表

如需测试本机或内网上游，必须显式开启兼容选项：

```bash
ALLOW_HTTP_UPSTREAMS=1 \
ALLOW_PRIVATE_UPSTREAMS=1 \
ALLOWED_UPSTREAM_PORTS=4318 \
npm start
```

不要在公网部署中开启 `ALLOW_PRIVATE_UPSTREAMS`。

### 浏览器和 HTTP 边界

- 校验请求 Host，阻止利用本地服务的 DNS 重绑定请求
- 修改状态的 API 必须携带同源操作标识
- 拒绝跨站 Fetch Metadata、错误 Origin 和简单表单 Content-Type
- 使用严格 CSP、Trusted Types、COOP、CORP 和 Permissions Policy
- 禁止页面嵌入、MIME 猜测和不必要的浏览器能力
- HTTPS 模式启用 HSTS
- JSON 请求最大 64 KiB
- 限制 Header 数量、请求读取时间、连接数和单连接请求数
- 默认最多同时运行 2 个分析任务和 4 个模型读取请求
- 每个任务最多保留 3 条实时进度连接
- 分析任务与创建它的设备绑定，其他设备无法读取或取消

### 防滥用

开始分析前必须完成服务端滑块验证：

- 挑战与 IP、匿名设备 Cookie 绑定
- 挑战 2 分钟后过期
- 服务端复核目标位置、拖动时长和轨迹
- 验证通过后签发短期、一次性凭证
- 成功启动分析后，同一 IP 或设备 5 分钟内不能再次启动
- 内存中只保留经过 HMAC 处理的 IP/设备键，不保存原始 IP

滑块和进程内限流用于提高自动化滥用成本，不是完整的身份系统。多实例部署应把挑战、冷却和登录限制迁移到 Redis 等共享存储，并继续使用 CDN/WAF 限流。

## 环境变量

### 基础配置

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 服务监听地址 |
| `PORT` | `4317` | 服务端口 |
| `PUBLIC_ORIGIN` | 空 | 公网 HTTPS Origin，例如 `https://planscope.example.com` |
| `ALLOWED_HOSTS` | 本机 Host | 额外允许的精确 Host，多个值用逗号分隔 |
| `ABUSE_SECRET` | 启动时随机生成 | IP/设备身份 HMAC 密钥，配置时至少 32 字节 |
| `ADMIN_PASSWORD` | 本机临时生成；公网禁用 | 管理后台密码，配置时为 16–256 字节 |
| `ADMIN_SESSION_SECRET` | 启动时随机生成 | 管理会话签名密钥，配置时至少 32 字节 |
| `PLANSCOPE_DATA_DIR` | `.data` | 管理历史和请求日志保存目录 |
| `MAX_HISTORY_RECORDS` | `5000` | 历史保留数量，允许 `100–20000` |
| `MAX_REQUEST_LOG_RECORDS` | `20000` | 24 小时请求日志容量，允许 `100–100000` |
| `MAX_REQUEST_LOG_BYTES` | `268435456` | 请求日志总容量（字节），允许 1 MiB–1 GiB |

### 上游策略

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `ALLOWED_UPSTREAM_HOSTS` | 空 | 允许访问的精确上游域名列表 |
| `ALLOWED_UPSTREAM_PORTS` | `443` | 额外允许的上游端口 |
| `ALLOW_HTTP_UPSTREAMS` | `false` | 允许 HTTP；只应用于隔离测试环境 |
| `ALLOW_PRIVATE_UPSTREAMS` | `false` | 允许内网/回环地址；不要在公网开启 |

开启 `ALLOW_HTTP_UPSTREAMS=1` 后会同时允许标准 HTTP 端口 80；其他端口仍需通过 `ALLOWED_UPSTREAM_PORTS` 显式添加。

### 代理和容量

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `TRUST_PROXY` | `false` | 是否接受可信代理提供的协议和客户端 IP |
| `TRUSTED_PROXY_IPS` | 回环地址 | 可信反向代理 IP，多个值用逗号分隔 |
| `FORWARDED_IP_HEADER` | `x-real-ip` | `x-real-ip`、`x-forwarded-for` 或 `cf-connecting-ip` |
| `MAX_ACTIVE_JOBS` | `2` | 最大并行分析任务数，允许 `1–20` |
| `MAX_STORED_JOBS` | `500` | 内存任务数量上限，允许 `10–5000` |
| `MAX_JOB_LISTENERS` | `3` | 单任务实时连接上限，允许 `1–20` |
| `MAX_CONCURRENT_MODEL_LOOKUPS` | `4` | 并行模型读取上限，允许 `1–20` |

只有完全隔离的测试环境才应使用 `ALLOW_INSECURE_PUBLIC_ORIGIN=1` 绕过非本机监听的 HTTPS 检查。

## 公网部署

非本机监听默认要求配置 HTTPS `PUBLIC_ORIGIN`，否则服务会拒绝启动。直接通过 HTTP 访问 HTTPS 公网配置时，服务返回 HTTP `426`。

反向代理示例：

```bash
HOST=0.0.0.0 \
PUBLIC_ORIGIN=https://planscope.example.com \
TRUST_PROXY=1 \
TRUSTED_PROXY_IPS=127.0.0.1 \
FORWARDED_IP_HEADER=x-real-ip \
ABUSE_SECRET='至少32字节的随机值' \
ADMIN_PASSWORD='至少16字节的长随机密码' \
ADMIN_SESSION_SECRET='至少32字节的随机值' \
PLANSCOPE_DATA_DIR=/var/lib/planscope \
ALLOWED_UPSTREAM_HOSTS=api.example.com \
npm start
```

部署时还应确保：

- 反向代理覆盖客户端伪造的转发 Header
- 入口启用 TLS、认证、请求大小限制和 CDN/WAF 限流
- 代理日志不记录 Authorization、Cookie 或请求正文
- 数据目录只对服务用户开放
- 多实例使用共享限流状态和带访问控制的历史数据库
- 不开启 `ALLOW_PRIVATE_UPSTREAMS`

## 常见问题

### 为什么提示“无法获取订阅数据”？

首个样本已经请求成功，但中转站没有返回或透传
`x-codex-plan-type` / `plan_type`。PlanScope 不会根据其他信号猜测订阅，
因此会停止剩余 99 次请求并提示上游开放订阅字段透传。

### 为什么提示只允许 HTTPS？

默认策略禁止通过明文 HTTP 发送 API Key。请优先使用 HTTPS。只有本机模拟或隔离测试才应启用 `ALLOW_HTTP_UPSTREAMS=1`。

### 为什么本机或内网地址被阻止？

这是默认 SSRF 防护。隔离测试可以显式设置 `ALLOW_PRIVATE_UPSTREAMS=1`，公网部署不能开启。

### 为什么不能再次分析？

成功启动一次分析后，同一 IP 或设备会进入 5 分钟冷却。模型读取也有独立的 5 分钟窗口。

### 为什么管理后台无法登录？

- 本机：查看启动终端中的临时密码，或设置 `ADMIN_PASSWORD` 后重启。
- 公网：必须显式设置 `ADMIN_PASSWORD`。
- 连续输错 5 次后，需要等待 15 分钟。
- 修改 `ADMIN_SESSION_SECRET` 或重启使用随机密钥后，旧会话会失效。

### 为什么公网监听时服务拒绝启动？

设置 HTTPS `PUBLIC_ORIGIN`、可信代理 IP 和正确的转发 Header。PlanScope 默认拒绝没有 HTTPS 边界的非本机监听。

### 端口 4317 已被占用怎么办？

```bash
PORT=4327 npm start
```
